## Key findings to write about (from evaluation)

- Dataset bias 1: all PhiUSIIL legitimate URLs are https homepages -> ML uses domain features only.
- Dataset bias 2: 97% of PhiUSIIL legitimate URLs start with www. -> caused ~20% false alarms on real URLs (docs.google.com, x.com); fixed by registered-domain features.
- Model accuracy on PhiUSIIL fell 85.2% -> ~81% after the fix, but real-world performance improved: honest model > inflated benchmark.
- QR decoder: 97.4% -> 100% after adding image clean-up + backup detector.
- Rules: recall 8% -> 31% (0 false alarms) after typosquatting detection, brand watchlist, Spamhaus abused TLDs.
- Reputation (Tranco top 100k): false alarms 13.5% -> 0.6%; only remaining false alarm: fastag.ihmcl.com.
- Limitation: 24 phishing URLs hosted on reputable platforms (ipv64.de dynamic DNS, gitbook.io, contaboserver.net, edgeone.dev) passed the reputation check - "living off trusted sites". Live feeds (OpenPhish/VirusTotal) cover this in deployment.
- Honesty note: rules were refined after analysing this OpenPhish snapshot, so a re-test on a fresh snapshot is the true held-out result.
